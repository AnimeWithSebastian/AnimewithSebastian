# Law #150 — Execution and Verification Integrity (added July 24, 2026)

**Status:** ACTIVE — HARD LAW
**Added:** July 24, 2026
**Applies to:** Every daily_combined run, without exception.

1. ACTUALLY RUN THE VALIDATOR. Before returning any manifest, actually execute
   validators/validate_dual_package.py against it and capture the real output. A self-reported "this
   would pass" is never a substitute for running the script. Any non-zero exit blocks sending per
   Step 6 — no exceptions for time pressure or model confidence in the draft's correctness.

2. ACTUALLY READ THE LIVE STATE FILES. Before selecting today's ideas, actually read the live
   blackout_state.json and sent_scripts_log.json from the repo, filtered to date <= today, per the
   cross-referencing workflow. Never proceed on memory or an assumption of their contents from a
   prior run or prior conversation summary.

3. CROSS-CHECK BOTH PACKAGES TOGETHER. Morning and evening packages must be generated and
   cross-checked against each other (distinct shows, formats, hooks, titles — see Step 4/Step 6) in
   the same pass before either is sent. Never validate one package in isolation and assume the other
   is automatically fine.

4. FLAGGED FAILURES ARE THE SYSTEM WORKING. If any check would genuinely fail, report it as failing
   and fix the draft. Do not soften, omit, or rubber-stamp a check to avoid blocking the run. A
   correctly-flagged failure is the system working as intended, not a problem to route around.
